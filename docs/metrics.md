# 재는 법 — MetricsOverlay

프레임을 재고, 어디서 새는지 보고, 숫자를 밖으로 꺼내는 절차. 그래픽 품질 티어
작업의 검증이 전부 이 문서에 의존한다.

---

## 1. 켜기

```
?debug=1
```

주소 끝에 붙이면 왼쪽 **아래** 초록색 숫자 배지가 뜬다. 같은 플래그가 lil-gui
튜닝 패널도 함께 연다 (그쪽은 오른쪽 위, `z-index` 가 겹쳐서 배지가 왼쪽에 있다).

**배지를 클릭하면** 접힘 → 요약 → 전체 → 꺼짐 순으로 돈다. 선택은
`msa.metrics.v1` 로 저장돼서 다시 켜도 유지된다.

배지가 **주황색**이면 프레임을 흘리고 있다는 뜻이다.

> ### ⚠ `?debug=1` 로 잰 프레임 시간은 배포 빌드의 프레임 시간이 아니다
>
> 패널 자체가 프레임을 먹는다. 실측으로 **두 배 가까이** 부풀린다. `fps` 와
> `frame` 을 절대값으로 인용하려면 패널을 **꺼짐**까지 돌린 상태에서 재거나,
> 콘솔에서 `__cap.metrics.snapshot()` 만 읽어라 — 아래 4절.
>
> 비교는 안전하다. A 안과 B 안을 **둘 다 패널을 켠 채로** 재면 오버헤드가 양쪽에
> 똑같이 실리므로 차이는 그대로 유효하다.

## 2. 전체 모드가 보여주는 것

| 줄 | 뜻 |
|---|---|
| `boot` | 네비게이션 시작 → 첫 프레임. Rapier WASM 컴파일 포함 |
| `fps` / `low` | 평균 FPS, 그리고 1% low (하위 1% 프레임의 FPS) |
| `frame` | 실제 프레임 간격. rAF 가 주는 값 |
| `tick` | `tick()` 전체 — 물리 + 게임 + 렌더 제출 |
| `phys` | `match.update(dt)` 만 |
| `steps` | 이번 프레임에 돈 물리 스텝 수. **60fps 면 2가 정상** |
| `acc` | 어큐뮬레이터에 남은 시간 |
| `drop` | 프레임 간격이 50ms 를 넘어 **실제 시간이 버려진** 프레임 수 + 버린 총 초 |
| `sat` | 스텝 드레인이 자체 상한(20)에 닿은 프레임 수. **0이어야 한다** |
| `ai` | 직전 AI 턴이 쓴 총 CPU, 그리고 한 프레임 최대치 |
| `mem` | `performance.memory`. Chromium 계열에만 있고 나머지는 `n/a` |
| `note` | 저해상도 렌더 타겟 → 캔버스. 둘의 차이가 업스케일 배율이다 |

### `drop` 이 왜 "밀림"의 정답인가

이 게임의 어큐뮬레이터는 **폭주할 수 없다.** 두 개의 클램프가 막는다:

- `Match.update` 는 한 프레임에 최대 20 스텝만 돌고 나머지는 `_acc = 0` 으로 버린다
- `main.js:frame` 은 프레임 delta 를 **0.05초로 자르고** 어큐뮬레이터에 넘긴다.
  1/120 기준 6 스텝이라, 위의 20 상한은 메인 루프에서 도달조차 하지 않는다

그래서 실패 모드는 죽음의 나선이 아니라 **조용한 시간 손실**이다. 프레임이 50ms 를
넘으면 클램프가 진짜 시간을 버리고, 개별 스텝은 전부 정확한 채로 시뮬레이션만
벽시계보다 느려진다. `drop` 이 그 프레임 수와 버린 초를 센다. `sat` 은 별개로
20-스텝 상한을 세는데, 여기가 0이 아니면 메인 루프 말고 뭔가가 어큐뮬레이터를
돌리고 있다는 뜻이다.

## 3. 재는 절차

1. 창 크기를 정하고 **고정한다.** 프레임 해상도가 창을 따라가므로 창이 바뀌면
   비교가 무의미해진다
2. 모드와 상대(AI/로컬)를 정한다. `label` 줄이 지금 무엇을 재고 있는지 찍는다
3. 30초 이상 플레이한다. 첫 몇 초는 셰이더 컴파일과 텍스처 업로드라 버린다
4. `__cap.metrics.resetWindow()` 로 롤링 통계를 비우고 다시 30초
5. `snapshot()` 을 찍는다

`resetWindow()` 는 `fps`/`frame`/`tick`/`phys` 만 비운다. `drop` `sat` `boot` 같은
누적 카운터는 살아남으므로 "이번 창에서 몇 프레임 흘렸나"를 따로 셀 수 있다.

### 무엇과 비교하는가

`main` 에서 같은 절차로 잰 값. 브랜치 하나에서 잰 절대 FPS 는 기계와 창 크기와
그날 브라우저가 하던 다른 일에 전부 묶여 있어서 혼자서는 아무것도 증명하지 않는다.

두 브랜치를 나란히 재려면 `git worktree` 로 옛 커밋을 꺼내 `node_modules` 를
심볼릭 링크하고 다른 포트에 `vite` 를 하나 더 띄운다. 같은 창 크기, 같은 모드,
같은 순서로 **번갈아** 재라 — 연달아 재면 기계가 더워지는 것이 곧 차이가 된다.

## 3.5 재면 안 되는 것 — GPU 시간

> ### ⚠ 화면에 실제로 그려지고 있지 않으면 GPU 시간은 잴 수 없다
>
> 이 저장소에서 실측으로 두 번 틀렸고, 두 번 다 그럴듯한 숫자가 나와서 한동안
> 몰랐다. 둘 다 적어 둔다.
>
> **1. 숨은 표면 + 손으로 민 `tick` + `gl.finish()`**
> 서바이벌 판을 2134x1600 · 4x MSAA · 블룸으로, 드로우 콜 39개와 삼각형 19412개를
> 실제로 제출하면서 쟀더니 **프레임당 0.154 ms** 가 나왔다. 그런 GPU 는 없다.
> 표면이 화면에 안 올라가면 컴포지터가 일을 버리고, 버린 일은 `gl.finish()` 도
> 기다리지 않는다. 손으로 미는 `tick` 은 **프레임을 세는 데** 쓰는 것이지 **재는
> 데** 쓰는 것이 아니다.
>
> **2. 중첩된 브라우저 창의 rAF 간격**
> 같은 장면 · 같은 창 · 같은 절차로 연속 네 번 잰 값이 61 · 82 · 92 · 124 fps
> 였다. 비교 대상 쪽도 같은 폭으로 흔들렸고 순서와 상관이 없었다. 앱 안에 박힌
> 브라우저 페인의 rAF 는 디스플레이의 수직동기가 아니라 **그 페인이 합성되는
> 주기**를 따라간다. 그 위에서 잰 fps 차이는 아무 뜻이 없다.
>
> `snapshot()` 의 **`hiddenFrames`** 가 그 사촌을 잡는다 — 페이지가 안 보이는데
> rAF 가 계속 도는 경우다. 0 이 아니면 `fps` `frame` 은 버려라. `tick` `phys` 는
> CPU 라서 살아남는다.

### 그래도 믿을 수 있는 것

화면이 안 보여도 이 넷은 정확하다. 그림이 무거워졌는지를 판단하는 데는 대부분
이걸로 충분하다.

| 무엇 | 어떻게 |
|---|---|
| 드로우 콜 · 삼각형 | `r.info.autoReset=false; r.info.reset(); __cap.tick(1/60);` 뒤에 `r.info.render` |
| GPU 자원 수 | `r.info.memory` (지오메트리 · 텍스처), `r.info.programs.length` |
| CPU | `snapshot()` 의 `tickMs` `physicsMs` — 렌더 제출까지 포함하고 프레젠트는 아니다 |
| 첫 화면까지 | `snapshot().bootMs`, 그리고 `npm run build` 의 `dist` 크기 |

`r` 은 `__cap.viewport.renderer` 다.

### 실제로 그렇게 낸 결론 (아트 디렉션 v3, 2026-09-04)

v3 열한 페이즈 전부를 `83c7a65` 와 비교한 것이다. 창 1280x800 · DPR 2 ·
서바이벌 · 로컬.

| | v3 이전 | v3 | |
|---|---|---|---|
| 드로우 콜 / 프레임 | 40 | 39~40 | 같다 |
| 삼각형 / 프레임 | 19414 | 19412~19414 | 같다 |
| 지오메트리 · 텍스처 · 프로그램 | 11 · 24 · 16 | 12 · 25 · 18 | 콘 채움과 구름 셰이더 |
| `tickMs` (4회 평균) | 2.57 | 2.22 | **−14%** |
| `bootMs` | 542 | 461 | −15% |
| `dist` 합계 | 4660 KB | 3736 KB | **−924 KB** |

`dist` 의 −924 KB 는 거의 전부 폰트다: 두 웨이트 1343 KB 가 한 웨이트 388 KB 가
됐다. 프레임 예산이 아니라 **첫 다운로드**이고, 이 방향 전환에서 가장 큰 성능
숫자다. 근거는 저장소 루트의 `NOTICE`.

드로우 콜이 한 칸 흔들리는 것은 그 순간 HUD 에 무엇이 떠 있느냐에 달린 값이라
차이가 아니다. 재려면 같은 상태에서 두 번 재라.

GPU 시간은 위의 이유로 **못 쟀다.** 그림이 무거워지지 않았다는 근거는 프레임당
드로우 콜과 삼각형이 그대로라는 것이고, 새로 생긴 픽셀 비용은 조준 콘의 채움
하나다 — 프래그먼트 셰이더에 텍스처 페치도 루프도 없고, 지오메트리는 화면 전체가
아니라 사거리만큼의 부채꼴이며, 조준 중이 아니면 `visible` 이 false 다.

## 4. 숫자를 복사해 오기

개발자 도구 콘솔에서:

```js
copy(JSON.stringify(__cap.metrics.snapshot(), null, 2))
```

패널을 켜지 않아도 `metrics` 는 `?debug=1` 이 있어야 실물이다 — 없으면
`NO_METRICS` 스텁이고 `snapshot()` 이 `{}` 를 준다.

`__cap` 에는 이것들도 들어 있다:

| | |
|---|---|
| `match` `physics` `view` | 시뮬레이션과 렌더 |
| `tick` | 프레임을 **손으로** 민다. 0.2x 보다 짧은 단계를 밟을 때 |
| `viewport` `gameCamera` `camTracker` | 화면과 카메라 |
| `hud` `cards` `cardFx` `victory` | UI 레이어 |
| `controllers` `setOpponent` | 좌석과 AI 전환 |
| `CONFIG` | 라이브 설정 블록 전부 |

`tick` 을 직접 부르는 것이 화면 관련 검증의 핵심이다 — 패널이 숨겨져 rAF 가 멈춘
상태에서도 프레임을 세울 수 있다. **세는 것뿐이다.** 그렇게 민 프레임의 시간을
재면 안 되는 이유는 3.5 절에 있다.

## 5. 로컬 서버에 붙이기

```bash
npm run server:lan
```

붙일 주소를 먼저 찍고 서버를 띄운다. 서버는 `0.0.0.0` 에 바인딩된다.

다른 기계에서 붙일 때는 **메뉴 → 설정 → 서버 주소** 에 찍힌 값을 그대로 넣는다:

```
ws://172.30.6.33:8787
```

`ws://` 또는 `wss://` 로 시작해야 통과한다. 빈칸으로 두면 `location.hostname` 에서
호스트를 따오는 자동 유도로 돌아간다 — 같은 기계에서 여는 동안은 그게 맞다.

주소는 `msa.profile.v1` 키로 localStorage 에 저장되므로 한 번만 넣으면 된다.
`?debug=1` 패널의 "서버 주소" 필드도 같은 값을 쓴다.

## 6. 저장소

키는 넷이다. 전부 try/catch 로 감싼 동기 API 다.

| 키 | 소유자 |
|---|---|
| `msa.marks.v1` | `MarkStorage` — 마크 |
| `msa.profile.v1` | `NicknameStorage` — 닉네임 + 서버 주소 |
| `msa.audio.v1` | `AudioSettings` — 볼륨/음소거 |
| `msa.metrics.v1` | `MetricsOverlay` — 오버레이 표시 상태 |
| `msa.online.handoff` (sessionStorage) | `OnlineSession` — 문서 간 핸드오프 |

측정 중에 이것들이 끼어들 수 있다는 점만 기억하면 된다: 마크가 많으면 부팅에
텍스처 생성이 붙는다. `boot` 이 기계마다 다른 이유 중 하나다.

## 7. 웹뷰 기본 동작이 어디서 막히는가

측정과 직접 상관은 없지만, 브라우저가 게임의 제스처를 가로채면 그것도 프레임에
보인다. 한 군데가 아니라서 표로 둔다.

| 동작 | 어디서 막는가 |
|---|---|
| 스크롤 / 러버밴드 | `styles.css` — `touch-action: none` + `body { position: fixed }` |
| 풀 투 리프레시 | `overscroll-behavior: none` + `body { position: fixed }` |
| 더블클릭 | `webview.js` 의 `dblclick` |
| 핀치 줌 | `webview.js` 의 `gesturestart/change/end` — WebKit 전용이라 `touch-action` 이 못 잡는다 |
| 우클릭 메뉴 | `webview.js` 의 `contextmenu` (문서 전체), `PointerRouter` (캔버스) |
| 선택 / 이미지 드래그 | `user-select: none`, 그리고 `webview.js` 의 `selectstart`/`dragstart` |

`styles.css` 에는 `input, textarea` 예외가 하나 있다 — 닉네임 필드는 한글 IME
조합 때문에 실제 `<input>` 이어야 하고, 캐럿을 놓을 수 없는 필드는 필드가 아니다.

## frame.js 정리 결과

지시서 §7.1 이 "검증된 사실"로 제시한 여섯 항목을 코드로 재확인 — 전부 사실.

| 항목 | 조치 |
|---|---|
| `playHeight = height` → 두 밴드가 항상 0 | 이유를 주석에 명시 (아래 참조) |
| `BANDS_MIN_SHARE` 참조 0회 | 제거 |
| `boardRectNormalised()` 항상 `{0,0,1,1}`, 호출처 0 | 제거 |
| `boardAspect` == `aspect` | 두 필드 유지, 밴드가 켜지면 갈라진다는 사실을 주석에 |
| `fieldAspect` 를 `resolveFrame` 이 안 읽음 | 거짓 주석 교체 |
| `TOP_BAND_NEED` / `BOTTOM_BAND_NEED` 상수 | `tokens.js` 의 SIZE/SPACE 에서 유도 |

**밴드는 죽은 코드가 아니라 대기 상태였다.** 배선은 전부 되어 있다 —
`HudLayer` 가 `FRAME.topBand` 로 카드 노출을, `CardHand` 가 `bottomBand` 로 손패
위치를, `Viewport.boardRect*` 가 포인터 리베이싱을, `GameCamera` 가 `boardAspect`
를 카메라 aspect 로 이미 읽는다. 켜는 데 필요한 것은 `playHeight` 한 줄이다.

켜지 않은 이유는 렌더 경로다. 카메라가 `boardAspect` 를 쓰는데 월드는 캔버스
전체에 그려지므로, 밴드가 0 이 아니게 되는 순간 두 비율이 어긋나 장면이 늘어난다.
예전에는 저해상도 타겟에 scissor 를 걸어(`Viewport.bindBoard`) 해결했고 PHASE 1 이
그 타겟과 함께 그 경로를 없앴다.

### 4/4 에서 실측으로 바뀐 것

1. **나가기는 점수판 줄에 둘 수 없다.** 처음에는 부록의 "프레임 왼쪽 위" 를 글자
   그대로 점수판 줄의 왼쪽 끝으로 읽었다. 점수판은 최소 줌에서만 나타나므로 대부분의
   시간 동안 **아래 줄이 위로 미끄러져 올라와** 그 자리를 쓰고, 그 줄의 왼쪽 끝에는
   턴 플레이트가 있다. 실제로 겹쳤다. 지금은 같은 줄의 왼쪽 끝을 나가기가 가져가고
   턴 플레이트가 그만큼 오른쪽에서 시작한다.
2. **구분선 위에 숨이 필요하다.** `dialogPanel` 은 푸터를 판 아래에서 재므로 내용의
   끝과 구분선이 정확히 같은 y 가 된다 — 위쪽 여백만 있고 아래쪽이 없었다. 선이
   마지막 줄의 디센더를 지나갔다.
3. **구분선이 `PANEL.padX` 상수를 읽고 있었다.** 인자로 받은 `padX` 가 아니라. 모달은
   자기 여백(36)을 쓰는데 선만 24 에서 시작했다.

### 3/4 에서 실측으로 바뀐 것

부록이 정한 숫자를 그대로 쓸 수 없던 자리가 셋 있었고, 셋 다 **알약**이 원인이다.
알약의 둥근 끝 두 개가 폭에서 먹는 것은 정확히 버튼 높이만큼이므로, 폭이 줄 때
높이가 따라 줄지 않으면 평평한 가운데가 사라진다.

1. **CHOICE 높이 64 는 폭의 상한을 받는다.** 256 폭 프레임에서 판이 190 이 되는데
   높이가 64 로 남으면 라벨 자리가 145 픽셀이고, "마스터 볼륨 70%" 가 잘렸다.
   가운데가 폭의 75% 아래로 내려가지 않게 높이에 상한을 걸었다.
2. **푸터 버튼 폭 150 은 `kx` 로 줄이지 않는다.** 줄였더니 71 이 됐고 "◀ 메뉴로" 가
   "◀ …" 이 됐다. 푸터 버튼은 여러 장이 쌓이지 않으므로 좁힐 이유가 없다 — 저술된
   150 을 상한으로, 자리가 허락하는 만큼 넓다. 버튼이 하나뿐인 화면은 절반을
   쓰지 않는다.
3. **세로는 탭·여백·푸터까지 함께 접는다.** 421x316 프레임에서 푸터 80 을 지키면

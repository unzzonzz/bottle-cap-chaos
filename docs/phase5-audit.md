# PHASE 5 — 화면 정보 감사표

승인 게이트 산출물. 구현(PHASE 6)은 이 표가 승인된 뒤에 시작한다.
읽기 좋은 판: 아티팩트 `화면 정보 감사표`.

## frame.js 정리 결과

지시서 §7.1 이 "검증된 사실"로 제시한 여섯 항목을 코드로 재확인 — 전부 사실.

| 항목 | 조치 |
|---|---|
| `playHeight = height` → 두 밴드가 항상 0 | 이유를 주석에 명시 (아래 참조) |
| `BANDS_MIN_SHARE` 참조 0회 | 제거 |
| `boardRectNormalised()` 항상 `{0,0,1,1}`, 호출처 0 | 제거 |
| `boardAspect` == `aspect` | 두 필드 유지, 밴드가 켜지면 갈라진다는 사실을 주석에 |
| `fieldAspect` 를 `resolveFrame` 이 안 읽음 | 거짓 주석 교체 |
| `TOP_BAND_NEED` / `BOTTOM_BAND_NEED` 상수 | `tokens.js` 의 SIZE/SPACE 에서 유도 |

**밴드는 죽은 코드가 아니라 대기 상태였다.** 배선은 전부 되어 있다 —
`HudLayer` 가 `FRAME.topBand` 로 카드 노출을, `CardHand` 가 `bottomBand` 로 손패
위치를, `Viewport.boardRect*` 가 포인터 리베이싱을, `GameCamera` 가 `boardAspect`
를 카메라 aspect 로 이미 읽는다. 켜는 데 필요한 것은 `playHeight` 한 줄이다.

켜지 않은 이유는 렌더 경로다. 카메라가 `boardAspect` 를 쓰는데 월드는 캔버스
전체에 그려지므로, 밴드가 0 이 아니게 되는 순간 두 비율이 어긋나 장면이 늘어난다.
예전에는 저해상도 타겟에 scissor 를 걸어(`Viewport.bindBoard`) 해결했고 PHASE 1 이
그 타겟과 함께 그 경로를 없앴다.

축소 4건, 제거 0건. §0.4 의 일곱 항목은 전부 유지.

| 화면 / 요소 | 판정 | 근거 |

| 스코어 플레이트 | **축소** | 캡션에서 턴 번호 제거. 컬링 캡션은 판정에 필요하므로 유지 |
| 클럭 바 / 노트 라인 | 유지 | 이미 조건부 표시 |
| 나가기 버튼 | **축소** | 텍스트 → `SIZE.buttonIcon` 아이콘. 터치 타깃은 오히려 커진다 |
| 리센터 버튼 | 유지 | 이미 아이콘 |
| 손패 (본인 / 상대) | 유지 | 상대 손패는 이미 `faceDown` |

| 메인 메뉴 제목 | **신규** | 유리 패널. 지금은 부제가 바닥 광원 블룸에 묻힌다 |
| 상대 선택 / 온라인 | 유지 | 세 경로가 각각 다른 일을 한다 |
| 설정 | **축소** | 서버 주소는 LAN 개발용 — 접거나 `?debug=1` 뒤로 |
| 마크 편집 | **축소** | 도구 아이콘을 `icons.js` 벡터로. 저장 128×128 은 프로토콜 고정 |

## 감사 기준별 결과 (§7.2)

1. **매 프레임 필요한가** — 스코어 캡션의 턴 번호, 나가기 버튼 라벨 두 곳이 걸렸다.
2. **두 표시가 같은 것을 말하는가** — 없다. 지시서가 예시로 든 승리 화면 중복은 이미 고쳐져 있었다.
3. **캡션을 더 짧게** — 알까기만. 축구 `3선승`, 컬링 `라운드 1/4 · 선공 P1` 은 이미 최소.
4. **제거하면 판정 불가인가** — §0.4 일곱 항목 전부 유지. 제거 제안 0건.

## 승인이 필요한 결정

1. **밴드를 켤 것인가.** 지시서 권장은 켜기. 비용은 블룸 체인에 보드 영역 scissor 재구축.
   세로 화면에서만 효과가 있고 가로/데스크톱은 동일.
2. **위 축소 네 건.** 전부 §0.4 를 침해하지 않는다.
